创建项目与技术文件场景
Create a Project & Choose a Scenario

Dashboard → New TD / DoC project → Create project
  1. 填写产品/项目标题、PS 编号、目标日期及产品用途/描述。专家选择客户；客户账号默认归属自己的客户。Enter product/project title, PS ID, target date and intended use/description. Experts select a client; client users are scoped to their own client.
  2. 选择文件场景。A 按单元分别建档并建立文件包总览；B 将该产品的全部包装单元合并在一套 TD/DoC 中。选择前确认制造商和文件责任范围。Select a document scenario. A creates per-unit files plus a package overview; B consolidates all units for the product into one TD/DoC. Confirm manufacturer and document scope first.
  3. 按实际情况设置食品接触、可重复使用、Art 9 包装类型和生物基原料声明。属性会影响适用性矩阵；不要为关闭条目而修改事实。Set food contact, reusable, Article 9 packaging type and biobased claim based on facts. These affect applicability; do not alter facts to close items.
  4. 可选地建立第一个单元，然后点击 Create project。后续可在 Overview 编辑项目属性。修改后检查重开的条目、合规指引和文件。Optionally add the first unit and select Create project. Edit profile later in Overview; after changes, inspect reopened items, compliance guide and documents.

PPWR Digital Platform03 · Compliance Guide

合规指引与法律级别
Compliance Guide & Legal Levels

Project → Compliance guide
  1. 先选择需要查看的包装单元；检查实施时间线、当前开放证据、截止时间、最低证据和缺口。列表可按级别过滤，点击条目跳转采集页。Select the relevant packaging unit. Review the implementation timeline, open evidence, due dates, minimum evidence and gaps. Filter by level and open an item from the list.
  2. 按法律状态安排优先级：Legally required now、Required from a later date、Recommended evidence、Good practice。推荐证据和良好实践有助于证明/减少问询，但并非自动的法定义务。Prioritize by legal level: currently required, required from a later date, recommended evidence and good practice. Recommendations/practices may support evidence or reduce queries but are not automatically legal duties.
  3. 确认每项要求在本包装上的适用性、条款依据与适用日期。查看“minimum evidence”完成情况和“still missing”，再打开对应条目处理。Confirm applicability, article basis and application date for the packaging. Check minimum-evidence progress and missing items, then open the relevant item.
指引标签 / Guide label如何理解 / How to interpret
Legally required now条款适用且当前阶段已生效；按期限和最低证据要求处理。
Applicable provision currently in force; follow due date and minimum evidence.
Required from a later date未来适用；可提前准备，避免将来返工。
Applies later; early preparation may reduce future rework.
Recommended evidence常用证明方式，不等同法定条文规定的唯一文件。
A commonly accepted way to demonstrate compliance, not necessarily a uniquely prescribed legal document.
Good practice额外实践建议；不应标示为法律强制要求。
Additional practice advice; must not be represented as legally mandatory.
法律级别由条目规则、项目适用性和法规适用日期组合计算。请阅读指引中引用的条款和来源；有疑义交专家确认，不把建议项误写为法定要求。
Legal level combines item rules, project applicability and regulatory dates. Read cited provisions/sources; refer uncertainty to an expert, and do not mislabel recommendations as mandatory.

PPWR Digital Platform04 · Packaging & BOM

包装单元与 BOM
Packaging Units & BOM

Project → Packaging & BOM
  1. 展开 + Add a packaging unit，填写名称、层级、包装类型、UPI、SKU、重量、尺寸、供应商/地点和图稿引用。点击 Add unit。Expand + Add a packaging unit. Enter name, level, type, UPI, SKU, mass, dimensions, supplier/site and artwork reference; select Add unit.
  2. 选择单元，展开 + Add a component。纸、塑料、标签、油墨、胶黏剂等按独立部件登记。填写材料、结构、材料组、重量、再生含量，并关联供应商库中的材料。Select the unit and expand + Add a component. Record paper, plastic, labels, ink, adhesives and other parts separately. Enter material, structure, group, mass, recycled content and link a supplier-library material.
  3. 保存后核对组件质量合计、材料组、SKU 和供应商关联；检查 Overview 的适用性矩阵。供应商名称文本不等于供应商材料关联。After saving, verify component mass totals, groups, SKUs and supplier links; check the Overview applicability matrix. A supplier name alone is not a material link.

模板导入 / Template workbook import

需要传统 BOM 导入时，下载空白 PPWR_BOM_V1.xlsx，按原表头一行一组件填写；在包装页拖入或选择工作簿。导入会按编号创建/更新单元和组件。导入后复核，勿把它与新版 Smart import 混为同一入口。

For the traditional BOM path, download the blank PPWR_BOM_V1.xlsx, keep headers and use one row per component; drop/select it on the packaging page. Import creates/updates units and components by ID. Review afterward; this is separate from Smart import.

先导出当前 BOM 留档；核对项目与编号再导入。更改已批准字段可能重开条目；删除单元会移除其组件及关联采集项。
Export the current BOM first. Verify project and IDs before import. Changes to approved values may reopen items; deleting a unit also removes its components and related collection items.

PPWR Digital Platform05 · Smart Import

智能文件导入
Smart File Import

Project → Smart import
  1. 拖入文件、文件夹或 ZIP，也可点击 Choose files/Choose folder。页面列出支持的 PDF、DOCX、XLSX、CSV、图片及 ZIP，合计上限以当前界面显示为准（代码默认 200 MB）。Drop files, a folder or ZIP, or use Choose files/Choose folder. The interface lists PDF, DOCX, XLSX, CSV, images and ZIP; observe the displayed total limit (200 MB in current code).
  2. 可用附录 A 文件夹名和描述性文件名帮助匹配，例如 PU-001_C04-16_HM-report_R2.pdf。导入器结合文件名、文件夹、可读取内容和过往更正提出条目/单元建议。Use Appendix A folder names and descriptive filenames, e.g. PU-001_C04-16_HM-report_R2.pdf. The importer uses filename, folder, readable content and prior corrections to suggest an item/unit.
  3. 检查暂存清单每个文件的置信度、建议条目、单元、类型、依据及内容摘录。逐行纠正；不相关文件选择 skip。未识别文件不要随意归类。Review confidence, proposed item/unit/type, matching reason and excerpt for every staged file. Correct each row; choose skip for irrelevant files. Do not guess classifications for unrecognized files.
  4. 选择默认包装单元；按需设置 Submit items for review 与 Run the AI pre-review now。检查无误后选 One-click import。Choose a default unit and set Submit items for review and Run the AI pre-review now as appropriate. Select One-click import only after review.
自动提交/初审是可选流程设置；即使开启，条目仍须专家审核。也可先点 Save corrections only 保存映射更正；Discard 丢弃暂存批次。
Auto-submit/pre-review are optional workflow settings; expert review is still required. Use Save corrections only to retain mapping corrections or Discard to discard staged files.
扫描版 PDF 和图片本试点不做 OCR，通常仅按文件名识别；识别置信度不是证据有效性结论。逐项核对原件、条目和包装单元。
The pilot does not OCR scanned PDFs/images; they are generally matched by filename only. Confidence is not a judgment of evidence validity. Verify each original, item and unit.

导入后 / After import

检查 Import history、证据库及条目状态；确认文件已正确关联，自动提交/预审数量符合预期。导入属于实际写入，不能只依赖 AI 识别结果。

Check Import history, Evidence vault and item states; verify file links and expected submission/pre-review counts. Import writes real records; do not rely on AI identification alone.

PPWR Digital Platform06 · Table Import

表格导入与列映射
Table Import & Column Mapping

Project → Smart import → Table data
  1. 从 Excel 复制表格粘贴，或上传 XLSX/CSV/TXT。至少需要一行表头和一行数据；点击 Parse table。Paste an Excel range or upload XLSX/CSV/TXT. A header and at least one data row are required; select Parse table.
  2. 核对解析出的表头、首行示例值和目标字段映射。每列选择正确目标；避免将单位重量映射到组件质量等语义不匹配。点击 Save mapping。Check parsed headers, sample values and target fields. Map every column correctly; avoid semantic mismatches such as unit mass mapped to component mass. Select Save mapping.
  3. 核对预计导入行数。单位列可按 UPI/名称新建或更新包装单元，BOM 列添加组件，条目字段列填写对应条目。已批准条目不会被覆盖。Check the expected row count. Unit columns can create/update units by UPI/name, BOM columns add components, and item-field columns populate items. Approved items are not overwritten.
  4. 若预览正确，选 One-click import of the table；否则修正映射，或用 Clear table 清除解析结果后重新开始。If the preview is correct, select One-click import of the table; otherwise correct the mapping or use Clear table and start again.
核实表格来源、单位、数值和每列含义；导入前保存原工作簿。自动创建/更新会改变项目数据。入库后抽样比对源表和平台记录。
Verify table source, units, values and column meanings; retain the source workbook. Import may create/update project data. Sample-check platform records against the source afterward.

导入记录 / Import history

历史显示提交人、文件数、表格行数、提交/预审数量及已学习的更正。它用于追踪批次，不代表已由专家批准。

History shows actor, file/table counts, submitted/pre-reviewed items and learned corrections. It tracks batches; it does not mean expert approval.

PPWR Digital Platform07 · Item Guidance

条目指引、预检与模板
Item Guidance, Pre-check & Templates

Data collection → open item → Evidence requirements / How to complete this item
  1. 先查看条目法律依据、项目/单元范围及 Evidence requirements。此区实时显示法律级别、适用日期、最低证据、已满足项、缺口和推荐证据。Review legal basis, project/unit scope and Evidence requirements. The live panel shows legal level/date, minimum evidence, met criteria, gaps and recommendations.
  2. 展开五个指引折叠区：法规描述/术语、所需信息和文件、分步示例、样本/模板/校验规则、监管来源。优先按本条目的格式及验收标准准备证据。Open the five guidance sections: regulatory description/terms, required information/documents, steps/examples, samples/templates/validation, and regulatory sources. Follow item-specific format and acceptance criteria.
  3. 填写字段时遵守即时格式提示。点击 Download fill-in template (Word) 或 Evidence list template 获取模板。Follow live format hints. Use Download fill-in template (Word) or the Evidence list template where helpful.
  4. 提交前点击 Check my entry。这是 dry-run：显示缺口、最低证据、适用状态和预审提示，不保存填写内容。根据结果修正，再保存或提交。Select Check my entry before submission. This dry run reports gaps, minimum evidence, applicability and pre-review hints without saving your edits. Correct issues, then save or submit.
字段校验不等于专家批准；最低证据进度仅反映平台配置的检查。平台生成/组装条目应从 BOM、证据登记或项目属性修改来源数据。
Field validation is not expert approval; minimum-evidence progress reflects configured checks only. For platform-assembled items, edit source data in the BOM, evidence register or project profile.

N/A 申请 / N/A request

客户展开 Not applicable to this packaging?，填写有事实和法规依据的理由（至少 10 个字符），点击 Request N/A；专家审核并确认后才关闭。适用性矩阵自动关闭的项目，先核对项目属性/BOM。

Clients open Not applicable to this packaging?, enter a factual/legal rationale (at least 10 characters), then select Request N/A. The item closes only after expert confirmation. For matrix-driven automatic N/A, verify profile/BOM inputs first.

PPWR Digital Platform08 · Evidence

证据上传与证据库
Evidence Upload & Vault

  1. 优先从对应条目上传，关联该条目和单元。选择文件后填写标题、证据类型、组件/整个单元、文件编号、签发方、签发日期及符合性状态。Prefer uploading from the relevant item to link evidence to that item/unit. Enter title, evidence type, component/unit, document number, issuer, issue date and actual conformity status.
  2. 遵照条目动态列出的格式；通用单文件上限为 25 MB。完成后点 Upload to the vault，再打开链接检查是否可下载、内容是否正确。Follow the formats listed for the item; the general single-file limit is 25 MB. Select Upload to the vault, then open the link to verify content and download.
  3. 进入 Evidence vault 按单元/类型筛选。Export Evidence List (.xlsx) 导出索引元数据，不会导出全部附件。删除前核对关联条目和副本。Filter the Evidence vault by unit/type. Export Evidence List (.xlsx) exports index metadata, not all attachments. Check links and backups before deletion.
提醒 / Indicator处理 / Action
Minimum evidence gap补足缺失内容；若证据引用到组件，确认组件关联。
Provide the missing content and verify component links where relevant.
Unusual file format查看该条目接受格式并选择合适版本；必要时咨询专家。
Check item-specific accepted formats and use an appropriate version; consult the expert if needed.
报告超过 24 个月
Older than 24 months		核验适用性与时效并处理提醒。该规则是平台预审阈值，不代表所有法规文件有统一有效期。
Verify relevance/currentness. This is a platform pre-review threshold, not a universal legal expiry period.
Non-conform如实登记结果并升级处理，不要用元数据掩盖不符合。
Record the actual result and escalate; do not hide non-conformity in metadata.
批准后条目通常锁定；修改附件请专家重开。证据上传成功不等于证据已被接受，且附件存储在当前试点的本地磁盘。
Approved items are generally locked; ask an expert to reopen them before changing attachments. Upload success does not mean acceptance; pilot attachments use local disk storage.

PPWR Digital Platform09 · Knowledge & AI

知识库问答与 AI 设置
Knowledge Assistant & AI Settings

知识库问答 / Ask the knowledge base

  1. 在 Knowledge & AI 或条目右侧 Ask about this item 输入中文/英文问题，提交后阅读回答和 [S#] 引用。Ask in Chinese/English from Knowledge & AI or the item's Ask about this item panel. Review the response and [S#] source citations.
  2. 点击引用核查来源文件、页码及其约束力。区分法规/具约束力文件与解释、标准或良好实践。若助手表示知识库未覆盖，不应把推测当成结论。Open citations to verify source file, page and binding status. Distinguish binding law from interpretation, standards or good practice. If the assistant says the corpus does not cover a point, do not treat speculation as a conclusion.
  3. 项目启动时完整全文索引可能仍在后台构建；此时检索使用精选知识池。知识库文件变化后由专家检查并按需重建索引。The full-text index may still be building after startup; retrieval then uses the curated pool. Experts should inspect knowledge-base changes and rebuild the index when needed.
受版权保护的 DIN EN 标准按标题索引，不提供其受保护全文。使用者应通过授权来源取得标准全文。
Copyrighted DIN EN standards are indexed by title only; protected full text is not reproduced. Obtain standards through authorized sources.

专家可选模型配置 / Optional expert model configuration

专家在 AI settings 选择 Azure OpenAI 或兼容端点，输入部署/模型、Endpoint、API version 和密钥，启用后保存并点 Test connection。密钥存于 git-ignored 数据文件；环境变量 PPWR_LLM_* 配置优先。

Experts choose Azure OpenAI or an OpenAI-compatible endpoint in AI settings, enter deployment/model, endpoint, API version and key, enable/save and select Test connection. The key is stored in a git-ignored data file; PPWR_LLM_* environment settings take precedence.
