① 技术文件出具情形（二选一）Technical-File Scenario (choose one)

两种情形的包装 ID、资料提交与草稿生成逻辑不同，可在下方卡片选择
情形 A单个包装类型独立出具技术文件（文件包模式）Per-package TD · Document Package Mode
每个包装类型各自独立出具一份 Technical Files（如：销售纸卡一份 TD、运输纸箱一份 TD……），多份 TD 汇集成一个「文件包 Document Package」，交由最终包装使用者（产品生产商）使用。
Each packaging type gets its own Technical Files; multiple TDs are compiled into one Document Package for the final packaging user (product manufacturer).
影响：每个包装类型拥有独立 TD 编号 + 独立 UPI/包装ID；资料按「包装」分别收集、分别审核；生成时为每个包装生成 TD/DoC，并附文件包总览封面与目录。
情形 B产品生产商即包装制造商 · 综合一份技术文件Consolidated TD · Producer = Manufacturer
包装使用方（产品生产商）同时也是包装制造商，将某款产品涉及的所有包装类型综合到一份 Technical Files 中统一出具。
The packaging user (product manufacturer) is also the packaging manufacturer; all packaging types of one product are consolidated into a single Technical Files.
影响：整个项目共用一份 TD 编号；包装注册表中的各包装类型在 TD §2 中统一列示，BOM/条款评估按包装分组，但证据登记册与结论汇总到同一份 TD；DoC 覆盖全部包装类型。

系统说明

关于本原型的边界与后续扩展
当前为前端原型：数据存于浏览器 localStorage，仅限单机使用；文件本体仅对小文件（≤1.5 MB）内嵌保存，大文件只记录元数据。
上线为多人在线系统：需对接后端（数据库 + 对象存储 + 审批工作流 + LLM/IMA 知识库 API），本界面可作为前端交互与数据模型蓝本。
草稿生成逻辑：仅批复「已通过 / 不适用」的素材进入草稿；情形 A 每包装生成独立 TD + 文件包总览，情形 B 生成综合 TD；证据编号 EV-xx 按包装自动生成。
AI 初审核：内置基于 IMA 知识库（kb_id 7432618899411080，含 Article 5–12 逐条解读 PPT、法规原文、FAQ、EN 13427–13432）的合规要点规则引擎；在线版将升级为 LLM + 知识库 RAG 审核。
